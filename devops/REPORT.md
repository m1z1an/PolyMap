После сообщения об ошибке `dockerDesktopLinuxEngine` Docker Desktop запущен через `docker desktop start`; WSL 2 и Linux engine работают. Образы `polymap-api:latest` и `polymap-web:latest` собраны из Dockerfile проекта.

PostgreSQL хранит данные в `polymap_polymap-db`, API применил `0002` и опубликовал пакет `4337101513b7fa43`. Добавлены `restart: unless-stopped`, healthcheck API и ожидание его готовности перед стартом веба. Порт 8080 освобождён от локального preview, ранее запущенного агентом; сайт теперь обслуживает контейнер.

Новая команда `powershell -NoProfile -ExecutionPolicy Bypass -File ./devops/start.ps1` проверена на Windows PowerShell: exit 0, `PolyMap is ready: http://localhost:8080`. Скрипт сохраняет существующий `.env`; создаёт файл со случайным паролем только при его отсутствии; запускает Desktop при необходимости, повторяет Compose до трёх раз и проверяет HTTP/состояние сервисов.

На контейнерном запуске проверены HTTP 200 для `/`, `/reports`, ссылки на место и `/api/maps/current`; GET заявок и анонимный PATCH возвращают 401. `alembic check` в API: `No new upgrade operations detected`. PostgreSQL и API имеют статус healthy, веб running. Повторный запуск сохранил опубликованную карту в томе. База не публикует порт на хост, API доступен через веб-прокси.

Реальный браузерный прогон обнаружил прежний лимит загрузки большого JSON-пакета в 5 секунд: запрос обрывался и при первом открытии приложение не использовало встроенный пакет. В `frontend/src/snapshot.web.ts` лимит пакета увеличен до 15 секунд (манифест остаётся 5 секунд). При сбое API существующий кеш сохраняет приоритет; без кеша загружаются встроенный манифест и данные с их собственной версией. Атомарная запись в IndexedDB сохранена. `frontend/tests/navigation.spec.ts` получил отдельную проверку отказа API с проверкой версии кеша и явное ожидание первичной готовности карты. Веб-образ пересобран с этим исправлением. `npm run check` проходит.

После пересборки карта, поиск, прямые ссылки и маршруты прошли Chromium desktop/Android и iPhone WebKit; offline прошёл desktop/Android. Полный прогон дал 10 passed, 4 skipped и один сбой подмены сети в новом тесте WebKit: service worker обходил перехват Playwright. Только для этого теста отключён service worker, после чего повторная проверка fallback во всех трёх профилях дала **3 passed**. Производственный код после этой проверки не менялся. Модерация в новой постоянной базе пропущена до разрешения на создание первого сотрудника; анонимные отказы 401 проверены отдельно. Команды: `npx playwright test --workers=1`, затем `npx playwright test navigation.spec.ts -g 'uses the packaged snapshot' --workers=1` из `frontend`.

Создание первого сотрудника `jakri` с паролем в `.env` отклонено автоматической проверкой разрешений: требуется явное согласие на конкретную учётную запись с доступом к заявкам. Генерация `revision --autogenerate` выполняется в копии каталога миграций, не создавая фиктивной ревизии в проекте. Backend: **3 passed**. TypeScript, Expo web build и проверка diff успешны.

Первоначальный параллельный холодный прогон превысил ожидание загрузки карты в 5 секунд; последовательный полный прогон успешен. ## Сквозной сценарий

1. Посетитель открывает существующую ссылку `/share/annotation?annotation=6a6adde3-f5bc-42bd-9f9c-ca0b45c311ca`, отправляет замечание без регистрации и видит номер. POST возвращает 201.
2. Анонимный GET `/api/reports` и PATCH заявки возвращают 401; чтение опубликованных карт остаётся публичным.
3. Сотрудник входит в `/reports`, выбирает статус «Новая» и реальный корпус места из исходного пакета, видит описание и названия.
4. Сотрудник указывает результат, выбирает «Исправлено» и отдельную опубликованную версию. PATCH возвращает 200, исходный `map_version` сохраняется, revision увеличивается; показывается ссылка на исправленный пакет.
5. Два конкурентных PATCH с одинаковым revision дают один 200 и один 409. После выхода прежний токен больше не позволяет читать или изменять заявки.

Исправленная публикация в проверке — синтетическая тестовая фикстура полного campus JSONB, а не заявление о реальном исправлении картографии. В интеграционных тестах также проверен исход «Не подтвердилось», отсутствие версии исправления и отказ для неизвестной исходной публикации.

## Skills и оркестрация

Системный skill-installer установил upstream файлы; пути и SHA перечислены в `agent-skills/README.md`. Find Skills применён к поиску FastAPI/Alembic; дополнительные skills из выдачи не устанавливались. Context7 CLI попытался получить документацию, но завершился `fetch failed`; использованы официальные [Alembic autogenerate](https://alembic.sqlalchemy.org/en/latest/autogenerate.html) и [SQLAlchemy ORM DML](https://docs.sqlalchemy.org/en/20/orm/queryguide/dml.html).

Repowise 0.61.0 установлен локально, выполнены `init --yes --no-prose --no-editor-setup --no-agents --no-codex --no-hook --no-distill-hook`, `risk --format json` и анализ целей `backend/main.py`, `frontend/app/reports.tsx`. Индекс построен без внешних модельных запросов; параллельный парсер недоступен в Windows sandbox, использован последовательный режим, init сообщает degraded. Risk рекомендовал полный прогон тестов из-за отсутствия карты покрытия и отметил зависимость CLI создания сотрудника от API. CLI проверен созданием тестового сотрудника. История содержит только один commit, поэтому количественная оценка риска и единственного автора имеет ограниченную ценность.

Реализацию выполнял субагент `gpt-6.1-terra` с reasoning `medium`, основной агент прочитал изменения, дал замечания и выполнил проверки. Предпочтение `gpt-6.1-sol high` сохранено в AGENTS.md; инструмент переключения уже работающей основной модели в этой сессии отсутствует, поэтому её переключение не заявляется.
